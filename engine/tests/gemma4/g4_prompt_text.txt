The Strata engine runs a mixture-of-experts language model on a single consumer GPU by keeping every routed expert in pinned system memory and a hot subset in video memory. During decoding, the GPU computes the attention and the router for each layer, then publishes the chosen experts to a pinned doorbell. A CPU thread that spins on that doorbell splits the experts into three groups: the ones already cached in video memory, a share of the misses that the copy engine moves across PCIe, and the rest, which the CPU cores compute directly from system memory with the same dot products that llama.cpp uses. The GPU waits on three flags in turn and sums the results. During prompt processing the engine works on chunks of two thousand tokens: the experts that are not cached are streamed from system memory while the GPU multiplies the ones that have already arrived, so the copy engine and the tensor cores stay busy together. The whole decoding step is captured once as a CUDA graph and replayed for every token, so the host never waits on a synchronizing driver call. Explain, in plain language and in about two hundred words, why splitting the work three ways can be faster than running every expert on the GPU over PCIe, and describe one situation in which the copy engine's share should be larger. Then list three measurements you would take to tune the split on a new machine, with a sentence about each.
