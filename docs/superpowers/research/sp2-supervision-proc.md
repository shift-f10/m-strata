# SP2 research (2026-10-13) — child supervision, PROC/EXT mapping, restart inputs, env allowlist

Source: read-only research subagent on branch sp0-foundation-hardening (working tree included the in-flight fix wave edits). Paths relative to secure_frontend/ unless noted.

## Defects found (spec must address)
- **PROC-05 (a):** POSIX `EngineStdioProcess::terminate` returns true once the LEADER is reaped (by `running()` or the SIGTERM grace loop) WITHOUT signalling the group → grandchildren still in the pgid, or ones ignoring SIGTERM, survive. Fix: always `kill(-pgid, SIGKILL)` even after the leader is reaped. **(b):** any descendant calling `setsid`/`setpgid` or double-forking escapes the group on Linux. Windows unaffected (`TerminateJobObject` always runs).
- `child_receives_exact_argv_and_env` does NOT assert the environment despite its name (`STRATA_T=1` passed, never checked).
- `docs/security/engine-protocol-limits.md:17` says the engine uses blocking `getline`; it uses `read(0)`/`_read(0)` in a thread (`generate.cpp:8860-8900`).
- Frontend has no SIGINT/SIGTERM handler → on signal death destructors don't run; engine (own pgid) lives until stdin EOF, finishing any in-flight generation (EPIPE ignored).
- Child env is `{}` always: a real CUDA engine on Windows likely cannot load `nvcuda.dll` deps without `SystemRoot`; ROCm needs a writable `TEMP`/`TMP`/`TMPDIR`. SP0 fake works only because it needs nothing.

## 1. Supervision today
- Production uses `EngineStdioProcess` only (`secure_server_main.cpp:275`); `EngineProcess` is test-only (keeps parent stdio, no pipes, no `--serve`, has `wait_for()` + exit code). Smoke binaries use neither.
- `posix_child_launch.hpp`: `prepare()` builds argv/envp/sweep limit (`_SC_OPEN_MAX` capped 65536, default 1024) pre-fork; `exec_child`: `setpgid(0,0)`, lift fds to ≥10 (`F_DUPFD_CLOEXEC`), optional stderr→/dev/null, `dup2` to 0/1/2 + report fd 3 (CLOEXEC), `close_range(4,~0U)` + fallback loop, `execve`, errno → fd 3, `_exit(127)`. Not done: signal mask/dispositions not reset (engine inherits SIGPIPE ignored), no `PR_SET_PDEATHSIG`, no `PR_SET_NO_NEW_PRIVS`, no `chdir` (inherits cwd), no rlimits.
- Windows: quoted cmdline with `--serve`; env block from allowlist only; stdin = single-instance named pipe `\\.\pipe\secure_frontend-<pid>-<n>` (`PIPE_ACCESS_OUTBOUND|FILE_FLAG_FIRST_PIPE_INSTANCE`, `PIPE_REJECT_REMOTE_CLIENTS`, buffer kMaxWriteLineBytes+4096, DEFAULT DACL), child end `CreateFileW` inheritable; stdout `CreatePipe` parent end non-inheritable; stderr inheritable `NUL`; Job `KILL_ON_JOB_CLOSE` only (no breakaway allowed); handle list {stdin,stdout,stderr}; `CREATE_SUSPENDED` → assign → `ResumeThread`. No `CREATE_NEW_PROCESS_GROUP`/`CREATE_NO_WINDOW` → child shares console, receives Ctrl-C.
- `terminate` POSIX: SIGTERM group → poll `running()` 10 ms to grace → SIGKILL group → ≤50×10 ms reap → close pipes → true (false if unreaped). Windows: `TerminateJobObject(job,1)` + wait grace. `cleanup()` = terminate(250 ms) + close all. `running()` POSIX `waitpid(WNOHANG)` (exit status DISCARDED in stdio class); Windows `WaitForSingleObject(h,0)`.
- Callers: `engine.start({exe,args,env={}})` → exit on failure; one protocol client + one chat service for process lifetime; `/health` healthy iff `engine.running()` && state ready|generating, engine field "failed" if not running; chat 503 if not running; READY awaited lazily on first chat (`ready_timeout` 30 s vs upstream 900 s; timeout non-fatal → retry next request; `/health` stays `starting` until a request). `for(;;) serve_one` single-threaded; nothing watches the child between requests.
- Engine dies mid-run today: `read_line` closed → `fail(closed)` → health failed → generic 503 → every later chat 503. No restart; exit status lost; `EngineProtocolClient` has no reset; `received_ready_` never clears → restart needs fresh objects or reset APIs.

## 6. Platform notes (knowledge; verify)
- Linux cleanup: pgid `kill(-pgid)` reaches members only; pgid valid while any member lives → signal after reaping leader is safe/needed. `PR_SET_CHILD_SUBREAPER` → orphans reparent to frontend (enumerate `/proc/<pid>/task/*/children` or `/proc/*/stat` ppid), doesn't survive frontend death. `PR_SET_PDEATHSIG(SIGKILL)` fires on forking THREAD exit → fork from long-lived thread, recheck `getppid()`; cleared on setuid exec; not inherited by grandchildren. cgroup v2 delegated sub-cgroup + `cgroup.kill` (5.14+) escape-proof but needs delegation (`Delegate=yes` / `systemd-run --user --scope`) → optional, detected. `pidfd_open`/`pidfd_send_signal` avoid pid reuse; `waitid(P_PIDFD)` 5.4+.
- Windows: Job KILL_ON_JOB_CLOSE auto-joins descendants (no breakaway flags set); nested jobs since Win8/2012; consider `JOB_OBJECT_LIMIT_DIE_ON_UNHANDLED_EXCEPTION` + `SetErrorMode(SEM_NOGPFAULTERRORBOX)` so abort doesn't stall on WER (PROC-04); `JOBOBJECT_BASIC_ACCOUNTING_INFORMATION.ActiveProcesses` = zero-descendants assertion; `JobObjectBasicProcessIdList` enumerates.
- Windows handle enumeration: child-side `NtQueryInformationProcess(ProcessHandleInformation=51)` → `PROCESS_HANDLE_SNAPSHOT_INFORMATION` + `NtQueryObject` (ObjectNameInformation can HANG on sync pipe handles — query names off-thread or skip); parent-side more robust: `PROCESS_DUP_HANDLE` + `DuplicateHandle` + `CompareObjectHandles` (Win10 1607+) vs canaries; `GetHandleInformation` only for own handles (assert canary WAS inheritable). Baseline holds loader/KnownDlls/ConDrv handles → assert canary absence, not exact count.
- Linux inspection: `/proc/<pid>/fd` + `fdinfo/<n>` (`O_CLOEXEC` = `02000000` in flags), same uid; `/proc/<pid>/environ` = INITIAL execve block (later setenv not reflected — fine for PROC-02); `/proc/<pid>/status` Uid/Gid/NoNewPrivs/CapEff/SigIgn/SigBlk. Same-uid caveat for PROC-03: `open("/proc/<engine>/fd/0", O_WRONLY)` reopens the pipe → injection possible; only other uid, non-dumpable target, or sandbox/LSM blocks → spec PROC-03 as "other user context", record same-user accepted risk (engine protocol can't carry a nonce without engine changes).
